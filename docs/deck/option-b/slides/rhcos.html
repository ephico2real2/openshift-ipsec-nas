WHY OPENSHIFT IS DIFFERENT

An OpenShift node is not a Linux server we configure by hand

Image-based

RHCOS keeps its operating system read-only; Red Hat says to avoid changing a node directly.

Managed by the cluster

The Machine Config Operator owns the node's files, through MachineConfigs per pool.

Network by policy

A tunnel is an NMState policy (NNCP), not a file in /etc/ipsec.d.

So the Linux procedure (a conn file and certutil on each host) does not apply. There is no turnkey Red Hat answer for per-node certificates.

Red Hat OpenShift documentation, About RHCOS (4.19) · doc 72, section 2

Red Hat's own documentation describes RHCOS as managed more tightly than a default RHEL install, with a read-only /usr, operating system changes handled by the Machine Config Operator, and direct changes to a node discouraged. Anything we put on a node goes through a MachineConfig, which applies to a whole pool, or through a pod.
