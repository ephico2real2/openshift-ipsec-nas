doc 70, What does not carry over: odd and even · doc 71, item 12

Our Linux standard picks a host's tunnel and NAS by whether its host name or the last octet of its IP is odd or even. On OpenShift that cannot work: nodes come from MachineSets with generated names and addresses, and they are added, removed and replaced over time, so odd or even is an accident that changes. Tracking it per node would be a manual list again. The OpenShift way is a node label, set and kept by the cluster: one rule for every node, applied automatically to each new one. Our plan replaces the per-host split with a per-cluster one: each cluster uses one NAS IP, alternating from cluster to cluster, set once in that cluster's values in Git. The NAS keeps whitelisting each cluster by subnet, which must be the node (machine) network, not the pod network. Both need no chart change; the NAS IPs are to confirm with the storage team.
