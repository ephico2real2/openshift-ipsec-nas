DESIGN RULES

How the DaemonSet is built

One pod, one node, one identity

Each pod gets its node's Secret and no other; it labels its data with its node, and OpenShift adds the node it scraped.

No reboot, no MachineConfig

Joining and renewal are automatic. Only revoking a removed node's certificate is a person's job.

Self-healing

Every 5 minutes it checks the certificate and the tunnel, and repairs what it can.

One collector for every option

The same code runs in Option B's DaemonSet and in Option C's metrics-only one: the same metrics everywhere.

Four rules. One pod per node, so a node's data is that node's: two checks on the dashboard catch a pod that reports the wrong node or a node reported twice. No reboot and no MachineConfig, because on RHCOS that is the only way to scale. Self-healing, because NetworkManager can report a connection as up while libreswan has no tunnel; the sync container restarts it. And one collector, shared by every option, so the dashboard and the alerts never depend on which option a cluster runs.
